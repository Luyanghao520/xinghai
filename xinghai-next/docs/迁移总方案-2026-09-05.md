## 二、阶段路线图

> 原则：**每阶段独立可验收、可暂停**；招新期旧站照常服务，新栈就绪一个换一个；
> 数据层只改 `src/lib/`，页面与接口不动（换 Postgres 的逃生门始终保留）。

### 阶段 1：申请账号体系 =「成员登录」✅ 已完成（2026-09-05）

学生从"只能填表"升级为"有账号、能跟踪进度"——这是你点名缺失的核心功能。

- **页面**：`/register` 注册（学号+密码+姓名+校区）、`/login` 登录、`/me` 我的报名进度、
  `/reset` 找回密码（对齐旧栈 register.html/login.html/reset.html）
- **API**：`POST /api/auth/register`（学号唯一性校验、密码哈希 scrypt）、
  `POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`、`POST /api/auth/reset`
- **数据**：复用 `applies` 表（pwd 列存哈希，旧数据兼容：首次登录提示重设密码）
- **后台打通**：审核状态变更后，学生端 `/me` 实时可见
- **验收**：注册→后台审核→学生登录看到结果，全链路走通；密码不以明文落库
- **预估**：一轮会话

### 阶段 2：干部账号 + 工作端总览

- `users` 表接入新栈（沿用旧账号数据，登录后角色=干部）；`/work` 总览页（子系统入口卡片）
- ADMIN_TOKEN 单口令保留为应急后门；新增登录限速
- **验收**：干部用旧账号登录 `/work`，未登录访问 `/work/*` 跳转 `/login`

### 阶段 3：成员管理页

- `/work/members`：列表/检索/编辑/删除/Excel 导入导出（对齐旧栈 `/api/members*` 全部能力）
- **验收**：录取产生的成员可被编辑修正；导入导出与旧库格式兼容

### 阶段 4：公告（第一个"前台新内容"）

- `bulletins` 表接入；前台首页/公告栏展示（置顶+级别），`/work/bulletin` 发布管理
- **验收**：干部发公告 → 前台立即可见

### 阶段 5：AI 答疑「小星」

- `kb.json` 原样接入：24 条关键词匹配 + 兜底话术，嵌招新页气泡组件
- 可选增强：接 LLM API（需要你提供 key，走环境变量），kb 作为首选命中
- **验收**：招新页能问"怎么加入/排练时间"并得到知识库回答

### 阶段 6：内部管理三件套（物资/报销/预约）

- 三张表 + 三个 `/work/*` 页面 + 审批状态机（提交→通过/驳回）
- **建议**：此阶段可在招新结束后再开工，期间干部继续用旧栈后台

### 阶段 7：CMS 内容编辑 + 首页内容填充

- 把 `content.json` 全部文案搬入首页（欢迎语/卖点/师资/组织架构/轮播/二维码）
- `/cms` 编辑页 + 图片上传（沿用 site_guard 二次口令思路，审计入 site_audit）
- **验收**：改文案不再需要改代码；首页与旧站内容一致

### 阶段 8：视觉设计（设计系统）

- 替换占位色板/字体/图标，统一组件样式（可引入 shadcn/ui 或参考 ixartz 主题），
  OG 分享卡片图（中文字体嵌入）
- **需要你**：提供设计参考/品牌色，或指定"照旧站风格精修"

### 阶段 9：上线切换

- Railway/Render 部署（持久卷 + `XINGHAI_DB_PATH`），绑定域名，`NEXT_PUBLIC_SITE_URL`，
  旧链接 301，旧站 PythonAnywhere 保留观察期后下线
- **需要你**：平台账号操作、域名与 DNS

## 三、关键技术决策

| 决策点 | 结论 |
|---|---|
| 鉴权 | 学生（applies）与干部（users）**两套账号分开**，Cookie 会话（HttpOnly+SameSite），密码 scrypt 哈希；旧明文/弱哈希密码首次登录强制重置 |
| 数据层 | 继续走 `DataStore` 接口 + SQLite（方案 A，Railway/Render 持久卷）；**严禁 Vercel 直跑 SQLite**；换 Supabase 时只换 store 实现 |
| 内容 | `content.json`/`kb.json` 文案原样复用，不重写；阶段 7 前直接读文件，之后可入库 |
| 双轨并行 | 招新期：报名主入口在**旧站**（或明确切到新栈，二选一，避免两边报名对不上账）；后台干部可先用旧栈 |
| 与 ixartz 方案关系 | 该方案的 11 功能清单已并入本方案 §1.1；其"模板组件化"思想由现脚手架的 Navbar/Hero/Card 组件体系等价实现，设计阶段可再吸收其视觉风格 |

## 四、风险与对策

1. **双系统数据分叉**：切换日前只在一个系统收报名（强烈建议新栈就绪后即切报名入口，旧站报名表单下线或跳转）。
2. **旧密码兼容**：applies/users 旧密码若为明文或弱哈希，强制重置流程兜底。
3. **SQLite 并发**：保持 WAL 模式（已开）；报名高峰写入量级（校园社团）远低于瓶颈。
4. **素材路径**：`static/uploads` → 新栈 `public/uploads`，迁移时统一复制并在 CMS 里更新引用。
